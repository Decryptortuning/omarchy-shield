## Native boot prerequisites

The raw `Image` is 45,746,688 bytes, exceeding both the observed 25.5 MiB boot partition and 32 MiB download limit. `Image.gz` is 17,246,875 bytes; together with the 732,023-byte diagnostic ramdisk and 72,330-byte evaluation DTB, its raw payload fits that partition before header/alignment overhead. This is a size check only. Exact installed-build stock images now establish gzip kernel payloads, Android header version 1 and 2,048-byte pages. The raw address fields need CBoot-specific interpretation and are not verified physical load addresses.

LineageOS source independently specifies `Image.gz` and Android header version 1. It also documents that the Mdarcy/Sif recovery-DTBO handoff is ignored on older platforms. Its bootloader allowlist and recovery-partition size differ from the owner's observations. Both the exact stock and inspected Lineage kernels enable legacy kexec. Lineage recovery now supplies verified privileged entry, but no kexec payload has been loaded or executed. An explicit-DTB handoff still requires memory and component review. No P2894 U-Boot configuration is qualified.

The [boot harvest](harvest/boot.json) obtained official Shield Experience 9.2.4 boot and vendor inputs matching installed build `13961458_4387.0822`. The embedded kernel configuration is byte-identical to the earlier stock capture. Local BSDIFF40 reconstruction produces a 20,575,528-byte recovery matching NVIDIA's target digest; boot/recovery RSA/SHA-256 footer checks pass using their embedded certificate. The whole OTA signature and hardware trust-anchor match remain unverified. This reconstructed recovery was subsequently written and booted successfully through the controller menu, qualifying the recovery-only restoration route. It does not provide a physical partition preimage or qualify restoration of other boot-chain components. The older developer-catalog 9.2.1 archive remains login-gated and is not selected for downgrade.

Stock restoration and verified Lineage root access establish a working recovery entry on the current bootloader. After an accidental owner reboot, the same verified Lineage image was written again; **Advanced → Enable ADB** then exposed UID 0 on `4.9.141-g9d1bd583388e`. The captured recovery command line has no `skip_initramfs`; this does not establish the arguments used in the earlier failed attempts. The live FDT is 565,070 bytes and contains memory/reservation, initrd and EMC-table data for offline review. Both fan modules are loaded; idle CPU/GPU readings were 53°C/51°C and the external A04 sensor zones are visible. These observations do not qualify full cooling or a desktop session. Existing pstore was empty. Raw captures stay private because they can contain identifiers and board security data.

The owner has authorized recovery-only diagnostic installation and matching restoration; no main boot, DTB or early firmware image was flashed. The diagnostic image's failure remains unresolved. Mainline entry still needs a private handoff DT with the live RAM banks, exclusions and trained EMC data, plus a reviewed CPU/device shutdown sequence before any kexec trial. The flat memory layout in the component DTB is not a qualified native handoff. The ARM development filesystem contains build accounts and signing state and is not an installable SSD image.

## Recovery handoff follow-up

The working recovery has active host1x/display and USB controllers. The recovery UI holds a framebuffer descriptor; GPU is unbound and the enumerated media clients are runtime suspended. Source review establishes normal display/xHCI/eMMC/CPU shutdown callbacks and explicit configfs gadget teardown, but pending host1x threshold work still needs an ordered shutdown design. No blanket device-unbind sequence is qualified.

The selected Linux kernel inherits an upstream assumption that identity domains start with untranslated hardware. Its first identity attach does not clear old SWGROUP ASIDs, and the current USB/MMC/PCIe DT nodes do not request an IOMMU attach. An [A04-only experimental reset](BUILD.md#a04-inherited-smmu-state) addresses that target initialization gap behind an explicit default-off parameter and early completion gate. It does not release native execution; live RAM exclusions/training, old-master quiescence and bounded diagnostics remain prerequisites.
