# Full-systemd qualification preparation

The published qualification checkpoint prepares a separate matched ARM root and binds a finite guardian/recovery pair. The [full-system ARM VM receipt](../validation-systemd-vm.json) qualifies that checkpoint's systemd/session core. The existing secure recovery control and physical USB remain separate until the native broker, materializer and root handoff complete qualification.

The working native pipeline has current source producers for bootstrap helpers, early runtime, capsules, package maintenance, layer materialization and full-systemd handoff. Retained full-system ARM systemd and maintenance VM runs passed their stated software scopes. A real recovery-RAM transfer exposed a remote writer-completion race; the corrected exact-byte reader now requires a size/hash/inode completion fence, and a full archive plus immediate ARM loader version check passed over the actual USB connection. The first attempted package run stopped before loader execution, watchdog arming or USB filesystem writes; that boot set remains consumed.

The selected kernel also contained the upstream `GET_SUBVOL_INFO` return-value regression. Patch `0017` carries [the exact upstream fix](https://kernel.googlesource.com/pub/scm/linux/kernel/git/torvalds/linux.git/+/75a41e3e51eb0d6f7a4969c5056298c2aa3e85f2). Fresh kernel209 compilation passed with unchanged configuration, DT and USB ACM module bytes. A read-only ARM VM observed correct ordinary subvolume records and return codes after the fix. Its overall witness then refused a separate account-baseline mismatch: the old desired root retained a build-only account absent from the original image. The current source correction seeds the original image's four independently pinned account files into a fresh host copy before adding only `shieldqual`; producer, installer and materializer share one strict account policy. New matched packages, root, profiles, layer, VM evidence and capsules are required before native release of this corrected cohort. Permanent boot and hardware parity remain open.

`prepare-qualification-overlay.py` renders the normal Omarchy UWSM session, temporary account policy, candidate-only root/home/log mounts and systemd units. `prepare-qualification-root.py` requires a pinned payload/overlay, verifies the reference, copies it to a new private host directory, excludes build/private state, creates the locked nonadministrative `shieldqual` account, runs the installed headless Tokyo Night theme leaf in a network-isolated ARM chroot, applies service masks and rechecks the full matched package payload. A partial output is retained and cannot be reused. Online onboarding and normal first-run completion remain pending.

`prepare-guardian.py` builds static AArch64 guardian/recovery artifacts without installing or executing them. Its shared exact source closure, kernel/config/DT inputs, root identity, overlay, helper and role form one sealed candidate. The generated C profile embeds that identity; the public default profile remains disabled. The runtime receiver checks the profile, artifact sidecar and installed helper/Python identities together.

`install-qualification-artifacts.py` admits pinned preparation, payload, artifact and profile receipts and rechecks the current producer/consumer closure. It creates another private host root, installs nine exact runtime/profile files, verifies their readback and repeats payload, account, home, policy and default-selection checks. It does not execute enabled entrypoints, activate units, select a boot root or write a physical device. The [host installation receipt](../validation-systemd-installation.json) records the executed scope.

The bounded qualification account has an explicit deny rule for twenty installed login1 power/boot actions, four systemd global-management actions and portable-image attachment, which can imply systemd daemon reload authorization. The complete 32-file action catalog is pinned and its incoming implication closure must be exactly these 25 actions. Recovery verifies the actual catalog, five primary XML/manual inputs and all root overlay files before readiness. Root recovery and unrelated subjects/actions fall through. The overlay ignores the installed logind key/lid/long-press and idle actions, disables forced Ctrl-Alt-Delete bursts and masks its target. An actual active local session produced 25 explicit NO results and denied direct power methods in the ARM VM; native effective policy remains unqualified. This temporary policy is not a claim of root/global-shutdown immunity or the permanent owner policy.

Sudo authentication policy remains unchanged. The VM separately proves the root policy's negative-only listing and denied command query, actual setuid elevation/drop, and the user's noninteractive authentication barrier. The user's password-required response is recorded as an authentication barrier, never as an observed command-authorization denial.

## Executed software and layer preparation

`prepare-systemd-vm.py` constructs a fresh isolated 24 GiB Btrfs fixture with the matched root/home/log layout, a small PID1 handoff and fixed root/user probes. `run-systemd-vm.py` permits one bounded run on its owned COW disk, retains a permanent attempt record and verifies the immutable baseline afterward. Real systemd, mount compression, actual modern VirtIO GPU/card linkage, native-entrypoint refusal, PAM/logind seat activation, user bus, setuid and bounded power controls passed. The virtual graphics fixture has no demonstrated software UWSM/compositor renderer; that scope remains blocked. Native guardian readiness is deliberately refused on the virtual board.

`prepare-native-qualification-layer.py` packages the admitted account files, complete themed home, policy/masks, runtime files and ancestor metadata as a private manifest plus content-addressed regular blobs. The [layer receipt](../validation-native-layer.json) records 10,388 entries and 6,536 unique blobs. `native_layer_reader.py` first authenticates an immutable copy against independently sealed compressed-length, archive, manifest, profile, payload and source pins, then applies bounded own-producer parsing. It returns immutable metadata and read-only blob views. The archive and account/profile data stay outside this repository. Physical preimage admission and a native writer are still required.

## Planned native preparation phases

The [fresh maintenance account witness](../validation-maintenance-accounts.json) now proves that the matched six-package update preserves the independently pinned original accounts on its owned VM disk, including a clean unmount and read-only readback. The original host-image account evidence and the tested desktop layer's account postimages are separately retained. A physical maintenance run must still admit the actual USB files, verify its own final postimages and seal them together with clean release and observed authenticated recovery; the VM receipt cannot substitute for that physical evidence.

The native controller and broker remain implementation work. Separate bounded boots keep package data and the complete home/runtime layer within the reviewed memory window:

1. Maintenance A creates new candidate snapshots and applies the matched packages with the required signature checks. A successful package receipt still requires clean USB release and observed authenticated recovery before advancing.
2. Maintenance B uses a fresh guardian and exclusive phase journal, admits the actual A postimages and account preimages, applies the exact qualification layer, verifies it and returns through clean release and authenticated recovery.
3. The systemd boot selects that verified candidate for the bounded desktop qualification. Both prior completion receipts and fresh boot/recovery/memory admission are required. Original default/rescue roots remain preserved.

Each boot has its own watchdog owner; no descriptor is transferred or reopened to join phases. Unknown or incomplete outcomes remain ineligible and are never automatically replayed. The native initramfs must stage the matching XUSB firmware before USB-root discovery and the four matching ACM gadget modules for early control. The VM handoff helper admits only its virtual board and cannot serve as the native loader.

Recovery must admit the actual USB Btrfs root/home/log after local mounts, verify startup masks and PID1 watchdog ownership, then announce readiness. Only then may the guardian acquire its sole watchdog descriptor and announce its first validated keepalive. The desktop follows that readiness through PAM/logind/UWSM. The guardian opens before boottime120 seconds, permits work only before540 seconds and never feeds beyond its cleanup cutoff or600 seconds. These are feeding deadlines; they are not a claim that hardware reset occurs at600 seconds.

The receiver never opens or feeds the watchdog. Its one cleanup attempt stops the temporary user, synchronizes the filesystem, unmounts home/log, verifies remaining Btrfs mounts read-only, verifies USB partition/whole-device read-only state, then requests guarded recovery within the existing deadline. It does not claim to unmount the root or guarantee power-loss durability. Blocking kernel I/O and recovery failures remain visible; no plain/global reboot fallback or automatic effect replay is provided.

## Native208 control integration in progress

The draft `native_boot_context.py` admits explicit early/root source inventories, phase inputs, the selected board/kernel/DT and guardian binding. The early runtime component has a separately pinned host provenance record; this is not a claim that native admission measures every already loaded interpreter/library byte. The new `prepare-native-capsule.py` drafts the host producer for that component, fixed native setup and exact phase inputs. It requires a fresh source cohort, rejects stale embedded maintenance APIs, stages the exact package archives and required signatures, shares pure plan/predecessor validation with the native reader, and checks the completed layer's source and root runtime identities. Host content admission cannot establish physical preimages or observed secure recovery.

The capsule producer builds a new private RAM seed, separate early/root session IDs and keys, a fixed command line, and copies the pinned Image/config/DT alongside the initramfs. Archive members need real declared directory parents; links resolve only inside the declared graph, so unpack writes cannot traverse aliases. The component does not contain BusyBox: its known static executable is an explicit `/bin/busybox` addition. Source inventory includes the unconditional unit-policy import in every phase. Compression, newc roundtrip and disk readback are assembly checks; all boot-set release, physical-fit and boot-ready flags remain false. This producer has not been imported or executed yet.

`native_gadget.py` prepares one checked ACM function and binds its UDC after descriptor readback. Configfs directory permissions are established explicitly. A bounded sysfs notification wait observes `configured` before the native owner opens the tty once; that preparatory state does not prove all endpoints or the PC collector are ready. `native_serial_link.py` emits unsigned `SNCR1` session hints only to trigger the host's single presealed probe. `native_control_protocol.py` supplies the authenticated PROBE/HELLO/ACK/PING/PONG exchange. A hung-up or uncertain stream is discarded, with no reopen, prefix replay or deadline extension.

The Windows bridge sends raw device bytes on stdout and its own lifecycle markers on a separate stderr pipe. `native_host_link.py` verifies the exact expected session, boot UUID, message sequence and typed cleanup evidence; device output cannot become a local bridge lifecycle observation. Early and real-root sessions use distinct presealed keys and session IDs. The real-root session requires the already authenticated boot UUID. Typed early handoff and phase A/B release consumers are now drafted; the outer host controller and observed-recovery completion producer remain unfinished.

`native_host_controller.py` now drafts the actual transport owner. Its parent owns one PowerShell process and a waitable session worker, and retains an independent absolute deadline while the worker handles pipe writes and private receipt fsync. The worker sends five-second liveness probes, bounds outstanding PONG waits, transfers the exact epoch tail to the independently sealed root session, and requires the bridge's STOPPED/EOF plus both actual process waits. Raw USB arrival may precede the separate CONNECTED metadata pipe, so bounded raw buffering preserves that ordering without treating USB bytes as local metadata. `PrivateFrameStore.retained_sha256` appears only after successful file/directory sync and its final deadline check. PowerShell's independent current-process deadline stays armed through serial close and final metadata output.

This transport owner still needs the fixed legacy loader/handoff coordinator and secure recovery observer. A retained terminal PONG can race recovery-triggered USB teardown before Windows processes STOP; the draft rejects an unproven bridge shutdown. That remains an operational discriminator to measure, without relaxing proof or replaying an attempt. The controller and bridge changes remain unimported and untested, and no new native execution is released.

`native_recovery_observer.py` now drafts the read-only return consumer. It independently admits the current LNX/SOS partition contract, checks root access with secure ADB on the selected recovery kernel, verifies actual block-node types/dev_t against sysfs and the legacy eMMC controller, and checks both critical image readbacks within one unchanged outer deadline. The initial authoritative observation requires the qualified SOS route; the passive normal-LNX boot is not a handoff grant. The returned SOS UUID must differ from both that initial boot and the native session. Exact read-only dispatch and bounded stdout/stderr drains prevent the observer from becoming a generic ADB command runner. Serial syntax alone is not proof of the physical USB transport; the outer handoff coordinator still owns that binding.

Only an actual successful transport completion plus the matching newly observed SOS return can produce the shared 22-field preparation content, and a false maintenance result cannot advance. Content construction does not publish or durably release a predecessor. The outer attempt journal/publisher remains to be implemented. These observer changes have not been imported or tested; limited manual read-only queries confirmed the expected live recovery kernel, root/authentication policy and eMMC controller metadata, without running the observer or reading new image hashes.

`native_attempt_journal.py` now drafts that claim and publisher. An exclusive `native-attempt` directory inside the independently pinned boot set consumes the attempt before device effects; existing or partial claims are never adopted. Publication binds the actual same Spec/Attempt/Observer, retained wire hash and 22-field content to fsynced/read-back records in a dedicated worker. The parent requires that worker's private result, actual successful wait and unchanged deadline before returning a `Published` value. Partial files or file presence alone are not that value and cannot automatically advance another phase. The fixed outer coordinator must still enforce qualification, physical USB binding and all legacy admission before release.

The new legacy source inputs preserve the previously exercised seven-client, thermal, storage, display, host1x idle, normal USB-host remove/VBUS-off and init-owned gadget teardown checks. They use the new fixed RAM/cgroup namespace. The C helper retains its watchdog description on known post-open failures; ordinary runner failures have an EXIT/fatal hold. HUP/INT/TERM deliberately remain ignored across interpreter startup and the whole legacy handoff, rather than being presented as catchable asynchronous aborts. Cancellation uses the fixed CANCEL marker only before RELEASE. After RELEASE, the runner's own checks/deadlines apply; the outer actor must not signal or kill the watchdog owner. This does not establish general SIGKILL, OOM, interpreter-startup or stalled-kernel recovery behavior.

`native_legacy_memory.py` drafts the actual four-segment placement parser using the current Image's header rather than older kernel sizes. It checks complete, nonduplicated reports, byte-loaded entry bounds, alignment, nonoverlap, the reviewed framebuffer-free window and ordinary AArch64 load flags. It does not independently identify segment contents or grant execution. Live FDT/carveout comparison, actual loader completion and `kexec_loaded` readback remain separate outer-actor requirements. None of these new source inputs has been compiled or executed.

`native_phase_coordinator.py` now drafts the actual outer sequence. A separately pinned release must bind the current source cohort, three host qualification records and the exact execution-input contract, including legacy tool qualification/artifact pins, ADB/FDT reader, reference FDT, current boot-partition baseline and selected physical USB policy. The coordinator claims the boot set, verifies the present recovery USB instance, enters the qualified SOS route once if needed, and binds subsequent shell/staging commands and the legacy runner to that actual SOS UUID. A changed boot is refused rather than silently adopted.

Before staging, it compares the complete reference/actual reserved-memory graph, all System RAM entries and runtime framebuffer declarations, derives persistent exclusions, and checks actual RAM filesystem identity/capacity. It verifies all staged bytes, one successful loader completion, actual loaded state and the nonoverlapping loaded extents against those exclusions. The collector must be ARMED and legacy readiness freshly checked before the one RELEASE commit. Cancellation is absorbing before that commit; an uncertain commit cannot be resent or cancelled as though it never happened. Transport/worker/Windows budgets are clipped to the unchanged outer deadline, with a proposed pre-arm reserve that remains unmeasured.

The outer sequence returns a preparation `Published` object only after actual transport closure, a newly observed authenticated SOS return, physical USB re-identification and durable publication. Its systemd return record deliberately establishes only control/cleanup/recovery, with desktop and hardware-parity qualification false. This coordinator is unimported and untested. Current compiler/runtime-component producers and fresh expected-A evidence still need completion, followed by a combined source freeze/review and the actual software/ARM/VM qualifications before any native release record may be created.

The draft real-root control service authenticates without waiting for guardian health, then announces readiness. The recovery receiver binds its one held private control connection before its own readiness; the guardian follows recovery readiness and the desktop follows the guardian. The RAM recovery drop-in uses `Wants` plus `After` for control startup: losing control must not stop the receiver when filesystem cleanup is needed. Exact unit/drop-in bytes and effective systemd fragment/drop-in paths are checked separately from the installed root overlay.

After completed read-only cleanup, the receiver records its exact receipt and requests a synchronous host-retention fence over the held, source-bound root connection. The host checks the typed receipt and digest, creates its private exact-frame file without replacement, and fsyncs that file and directory before sending a receipt-correlated PING. The native endpoint must completely transfer its matching PONG before acknowledging the local RPC. The RPC cutoff is the earlier of now plus two seconds and the existing cleanup deadline minus three seconds; these are proposed software reserves, not measured transport guarantees. Failure preserves the completed RO observation and never dispatches the restart helper. Successful receipt retention still does not prove that recovery boot happened.

`native_root_storage.py` currently provides read-only USB geometry, ancestry, held-node identity and Btrfs primary-superblock admission. It does not mount, clear block read-only flags, install or grant a writer lease. Its restrictive release helper requires caller-proven actor cleanup and unmounting; Btrfs mount device numbers are anonymous, so it explicitly rejects remaining Btrfs mounts instead of relying on a physical device-number comparison.

The draft RAM PID1 now lives in `native-boot.py`. Its systemd path verifies both independently pinned prior completions and their actual USB journals, original roots/accounts/default, the complete six-package/module/loader profile and the complete desired layer before activating the selected root/home/log mounts. It stages the exact RAM unit and udev policy, checks the selected real-root runtime, positively reaps its helper children and requires actual `ECHILD`. The new root is `/newroot`, outside the `/run` mount which standard util-linux `switch_root` moves. The early channel's exact prepared-handoff frame is retained by the host before its correlated PING/PONG. Only that explicit gate changes the host to the separately sealed root session and transfers the exact unconsumed stream tail. This is preparation evidence, not proof of a successful PID1 exec or desktop.

`native_children.py` keeps one-shot child attempts, private nonblocking result pipes and actual wait statuses separate. A guardian closing its stdout is expected and does not prove its death or readiness. `native_mounts.py` owns the fixed initial namespace's top/candidate mount targets; after caller-proven worker relinquishment it requires normal unmounts, remaining-mount checks and USB read-only readback. A failed or busy teardown cannot become a clean-release receipt. The C path checks its absolute deadline again after tty close, which may block in the selected serial driver's FIFO-close path, and immediately before PID1 exec.

Role1 now emits one `SG_RECOVER_READY` event on its already held recovery connection after its first validated keepalive. That event only wakes the RAM supervisor: actual pinned owner, health, work phase and reserve checks still admit the worker. Role2 retains systemd notification. The per-file worker admission helper caches a real status for at most half a second and rechecks actual clock, owner pidfd and all existing freshness/reserve predicates on every call. It never feeds or extends the watchdog. Socket EOF can precede pidfd death notification; pending loss stops work but cannot grant a fresh cleanup window or restart permission. Observed cutoffs can only shrink.

The phase-B FD-based materializer is now drafted in `native_layer_writer.py`. It admits all exact expected-A preimages and all four desired account tables before destination writes, preserves existing ancestor-only identities, creates a distinct exclusive phase journal and verifies all final postimages. Only the runtime directory and two explicitly named policy directories gain creation roles in the layer producer; other missing ancestors are refused. Materialization is not clean USB release. The package metadata verifier now requires an explicit owned executor, including its `bsdtar` reads, so a native transaction cannot launch hidden unbounded child commands.

The actual A/B supervisor is drafted in `native_maintenance.py`. It consumes the guardian's one readiness hint but separately admits pinned work status, checks physical preimages before RW, seals the job for the assigned stopped worker, and requires the subreaper's actual successful wait/EOF plus its master/ECHILD report and an independently empty leaf. Package workers may create only seven declared bindings. Completed jobs still require original profile/account/default checks, ordinary sync/unmount, block RO readback and a retained authenticated release fence before the fixed recovery helper. Retention does not prove recovery. A failed cancellation cannot suppress the independent guardian abort; a failed control fd is disarmed without a potentially blocking close ahead of writer cancellation. The existing absolute guardian deadlines do not change.

`qualification/native-init.c` drafts the actual initial PID1 producer for proc/sys/dev/run, devpts/shm, cgroup2/configfs, a fixed private RAM seed copy and the four exact ACM modules. Each bootstrap child needs a positive wait and the final process tree needs actual ECHILD before Python replaces PID1. Its `/init` ELF becomes a mandatory early source pin. It does not mount USB/eMMC, open the watchdog or request a reboot. Its early startup budget is proposed and unmeasured.

The early runtime, capsule and outer host producers are implemented. Their retained proofs keep their exact source and input scope. The current new-kernel/account-baseline integration still needs a complete matched rebuild and read-only expected-A witness before package/layer/systemd boots can proceed. Hardware collection has a reviewed design but no implemented telemetry contract. Protocol and cleanup fixtures have earlier passing software evidence; that evidence does not qualify a changed whole cohort or the physical final-PONG/serial-stop/recovery race. No native package transaction, full-systemd Shield boot, permanent launch or feature/performance parity is claimed for the corrected cohort.

## Next native run acceptance order

The next controller and collection bundle must implement and review this order before release. These are planned checks, not implemented collector results:

1. Admit current LNX/SOS recovery hashes, exact kernel/config/restricted DT, matching installed modules, USB identity and candidate root. Preserve the original default root and rescue snapshots. Keep eMMC writes and unrelated storage outside this run.
2. Prove systemd PID1, required root/home/log mounts, manager watchdog settings, guardian readiness and sensor/fan health before starting a desktop or workload. Establish authenticated host collection before effects; insufficient reserve or missing control ends work.
3. Prove the normal user session, shell/bar IPC, terminal, hardware Nouveau renderer and physical display mode. Capture screenshots, compositor logs, all underflow counters, kernel faults and actual application results. A device node or screenshot alone is insufficient.
4. Qualify a small designated USB scratch file with write/fsync/readback/hash/removal; inventory eMMC read-only. Capture USB device/gadget state, CPU topology/online state, memory/zram and thermal readings. Admit each bounded workload against the guardian's remaining reserve.
5. For enabled and wired hardware, test available Ethernet link/traffic and audio routing/playback. Inventory Wi-Fi/Bluetooth/video/Vulkan firmware, drivers and userspace separately. Disabled DT nodes, unavailable peers or absent firmware remain blocked tests, not passes. Pairing, network credentials or physical observations require the actual setup.
6. Stop workloads before the finite work cutoff. Prove owned cleanup/read-only state, observed secure recovery return and host receipt collection. Compare recovery hashes and distinguish a requested reboot from an observed reboot. Preserve failed or uncertain outcomes without replay.

Broader modes/hotplug, all-core load, DVFS, automatic cooling, radio coexistence, codec acceleration, suspend/wake and unattended permanent launch remain separate acceptance work. A bounded systemd desktop run is a prerequisite to that matrix, not full parity.

The current restricted DT keeps PCIe Ethernet, SDIO Wi-Fi, UART Bluetooth and HDA/board sound nodes disabled. Those functional tests remain blocked in the next unchanged-DT run. Native graphics, USB/root/control, read-only eMMC, fixed maximum fan/sensors and single-CPU observations are the initial supported qualification scope.

The current matched skeleton also contains an x86-64 Mason `shfmt` cache. Its ELF architecture was checked in the retained host copy. That editor-tooling gap needs a package-level ARM correction; it is not silently removed or counted as working by root preparation.
