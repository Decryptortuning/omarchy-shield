# Finite Shield guardian draft

This source is for the restricted A04 diagnostic candidate. `profile.h` deliberately disables both roles. The host checks in [the receipt](../validation-guardian-host.json) exercise actual pure state/wire code and a disabled ARM entrypoint; the enabled native guardian remains unqualified. This is not an indefinite desktop watchdog service or an AUTO fan policy. Source-bound profile production, systemd units and the recovery broker now have [host preparation evidence](../validation-systemd-preparation.json); installation, boot-controller integration and native qualification remain open. No Shield device access accompanied these host checks.

Only `--run` is accepted. Role, candidate digest, kernel release, identity, register addresses and timing are compile-time inputs; neither arguments nor control packets can select them. A reviewed producer must replace the disabled profile as part of a candidate-bound build. The candidate string is an integration identity, not an independent runtime measurement of the executable, kernel, DTB or root filesystem. The outside qualification/controller cohort must bind those artifacts and the recovery contract before enabling it. A profile without that binding is a gap, not qualified coverage.

## Processes and effects

`main.c` is the sole watchdog owner. It admits the exact A04/Darcy/T210 identity, diagnostic stamp, named cmdline assignments including the unique compiled `shield.guardian` candidate, fixed PWM polarity/period/cooling levels, absence of fan cooling maps, and watchdog driver/device identity. It discards inherited descriptors, prepares its sockets, installs signal handlers, then forks the sampler **before** opening `/dev/watchdog0`. There are no later fork/exec calls. The worker receives no watchdog descriptor. There is no owner logging; all owner sockets are nonblocking and work per loop is bounded. In FAULT_HOLD the 100ms idle poll uses fd=-1, so a dead worker's persistent EOF/HUP cannot turn that hold loop into a busy spin; control and recovery are still serviced on subsequent iterations. The only post-open device calls are descriptor identity checks, `WDIOC_GETSUPPORT`, `WDIOC_GETTIMEOUT` and `WDIOC_KEEPALIVE`. It never reads WATCHDOG_SYSFS attributes, changes timeout/options, writes magic-close bytes, closes/reopens that fd, or exits through a programmed path after successful open.

`sampler.c` resolves unique `cpu-thermal`, `tmp451` and `pwmfan` instances, pins their sysfs directories, checks hwmon OF compatibles and uses no-follow attribute opens. Only this worker reads sysfs or maps `/dev/mem`: a fixed **read-only** page at `0x60005000`, with CFG@0x100=`0x8017`, PTV@0x70=`0xc3938700`, STS@0x104 bit0 active and PCR@0x74 captured for status. There is no generic MMIO or register-write interface. The kernel's inherited-watchdog branch also checks the signature on each keepalive.

The only cooling writes are fixed `pwm1_enable=2` followed by `pwm1=255`, once after admission. Readback thereafter must remain exactly 2/255. CPU, TMP451 local and remote temperatures must each be at least -40000 and below 70000 millidegrees C; remote fault must be zero. Tach `fan1_input` must be positive and at most 999999. Zero RPM is allowed only during the first four seconds after the initial maximum assertion, before readiness; the grace never restarts. A sampling pass taking over one second fails. Fresh status requires a completed sample at most three seconds old. A sysfs completion timestamp does not prove a new physical sensor conversion, and unchanged numeric temperature is not used as a stale heuristic. TMP451 remote attachment and a calibrated acceptable RPM range remain unqualified. Missing devices are reported while pre-open discovery continues; malformed reads, duplicate discovered names, changed readback, failed timer identity and sampling loss fail closed.

## Deadlines and state

All deadlines use absolute `CLOCK_BOOTTIME`, including suspend time. Opening must finish strictly before boot second120. The work cutoff is boot second540, final cleanup cutoff boot second600. An earlier QUIESCE sets cleanup to `min(now+60s,600s)`, and repeated requests cannot move it. At540 the owner automatically enters QUIESCING. There is no new-work allowance in that phase; continued keepalive is conditional on healthy samples and ends at its cutoff. A fault irreversibly enters FAULT_HOLD and immediately withholds keepalive while retaining the same fd. Subsequent STATUS, ABORT, QUIESCE, signals or samples cannot restore feeding. Worker death, recovery disconnect, notification failure, backwards/failed clock, stale samples, watchdog API failures and missed ping bounds fault in the same way.

The first explicit keepalive establishes WORK. Later keepalives are due every30 seconds on the initial schedule; lateness above5 seconds or an observed gap above60 seconds faults. Completion taking over one second or crossing an absolute cutoff faults. Kernel IOCTL execution is not preempted by this userspace source; a stalled kernel can exceed software timing bounds. The hardware reset is the fallback, not a claim that every userspace action completes by a deadline.

These software windows are not a hardware time-left estimate. Native75 observed the last stream about196 seconds after its final ping before a watchdog reset; that is not a guaranteed minimum reset interval. There is no `GETTIMELEFT` claim and no “240 seconds remaining” status field. Recovery must fit the separately reviewed owned cleanup contract.

## Control and readiness ABI

`guardian.h` defines fixed little-endian request116/status248 structures with size assertions. Character arrays are raw candidate64 and boot UUID36 bytes without NULs; all reserved fields are zero. One request and one response use each connection. No ancillary descriptors, truncated packets, mismatched candidate/boot instance or non-root credentials are accepted. The directory `/run/shield-guardian` must be root:root0700 (systemd may create it); `control.sock` is created0600 and an existing socket is refused, never replaced. Listener and clients use AF_UNIX SOCK_SEQPACKET and SO_PEERCRED uid0/gid0. Up to four clients are admitted with bounded250ms request waits and bounded accepts/drains per loop. Failed delivery does not block the owner or confer any allowance.

Request opcodes: STATUS=1 with reason0; ABORT=2 with reason`SG_CLIENT_ABORT` (9); QUIESCE=3 with reason0. `request_result=0` means accepted,1 means rejected. STATUS does not reset any timer. Phase enum: PREOPEN0, ARMING1, WORK2, QUIESCING3, FAULT_HOLD4. Fault enum is in `guardian.h`; only the first fault is retained. Response flags: bit0 watchdog fd acquired, bit1 current sample healthy/fresh, bit2 WORK before the absolute work cutoff. Consumers must check candidate, boot, role, phase, fault, timestamps, sample evidence and available absolute budget; flags alone are insufficient. Temperature/RPM fields are signed32 values encoded little-endian; timer fields are unsigned32. Status reports the owner's boot clock, last sample/ping, fixed work cutoff, possibly shortened cleanup cutoff and counters. It neither grants a requested duration nor reports hardware reset time remaining.

Role2 requires direct parent PID1 whose `/proc/1/exe` is `/usr/lib/systemd/systemd`. Its inherited `NOTIFY_SOCKET` is prepared before opening the watchdog. Exactly one nonblocking real `READY=1` datagram is sent only after complete admission, a healthy sample, watchdog identity/API checks and a successful explicit keepalive. Failure faults and retains the fd. The notify address carries readiness only; it cannot alter policy or deadlines. Role1 uses the same health/state protocol without a systemd readiness datagram. A Type=notify unit must preserve the owner after open: Restart=no, no startup/stop timeout that escalates to SIGKILL, no owned-cleanup command that stops its unit. The qualification renderer provides these units, but host rendering and root preparation do not qualify their live readiness graph.

## Recovery boundary and remaining work

Before it starts, an owned broker must create root:root0700 `/run/shield-recovery` and a root:root0600 AF_UNIX SOCK_SEQPACKET listener at `/run/shield-recovery/request.sock`. The guardian connects before opening the watchdog and requires root uid/gid peer credentials. The broker receives the same116-byte request, op4 for FAULT with the latched fault reason or op5 for QUIESCE with reason0, bound to the compiled candidate and current boot UUID. It must keep the connection open without sending replies; unexpected data or disconnect faults. Each transition is sent once nonblocking; no successful send is claimed as an acknowledgement of cleanup. The broker must validate the sender/candidate/boot and perform the independently bounded owned cleanup/recovery action. It must never stop the guardian, feed the watchdog, change cutoffs, or run a global shutdown as this request's implementation.

The precise composed DT/sysfs paths and direct systemd parent/executable requirement have not been exercised on a new candidate. Full board DTs with fan cooling maps deliberately fail admission. Host production and artifact/source identity checks are implemented. Installation, mutually exclusive owner enforcement outside the watchdog's exclusive open, actual broker cleanup, live service readiness/ordering and complete native verification remain open integration work. A competing privileged fan writer cannot be made impossible by sysfs readback; admission plus the unit/ownership policy must prevent one. The code cannot survive SIGKILL, OOM kill, process crash or global shutdown while retaining an fd; closing a nowayout watchdog can itself cause another kernel keepalive, and that branch must remain separately bounded and reviewed. No immunity is claimed.

`state.c` exports pure state/profile/health functions for later meaningful tests of cutoff boundaries, stale/future/reordered samples, irreversible faults, shortened quiesce windows, ping latency and exact profile rejection. `tools/check-guardian.py` compiles the actual pure state/wire harness and checks its packets with the Python consumer, then runs the unchanged disabled profile under ARM emulation. Those checks do not execute an enabled hardware entrypoint. The combined source/profile/units/broker cohort has host-only source review and preparation evidence; it still needs integrated installation and native qualification.
