# Darcy integration candidate review

Review date: October 14, 2026. Scope: inactive firmware staging, controller configuration, fan/PWM producer and consumers, diagnostic component validation and a static ARM64 kexec helper. The source/interface review is complete for this candidate; [build and test evidence](validation-darcy-integration.json) records the resulting artifacts separately. No native execution, firmware activation, bootloader change or device write is part of this batch.

## Reviewed interfaces

- `firmware-darcy.lock.json` pins 41 selected payload/reference/notice inputs to the immutable harvest. The stager writes a new inactive directory and never changes request-path firmware or calibration data. Stock radio inputs require later board/MAC/license review; codec inputs remain vendor-interface references. `audit-hardware.py` verifies the staging lock/files and reads installed request-path bytes separately, including compressed package firmware.
- `HID_NVIDIA_SHIELD` requires USB HID, Bluetooth HIDP and LEDs. The fragment enables those dependencies, the controller module and force feedback; the Darcy matrix requires the actual module. This adds no microphone, IR or unrelated remote claim.
- Tegra's PWM provider accepts software inversion only when `usage_power` permits a shifted waveform. Normal-polarity consumers retain their existing duty. The selected A08 DT changes the shared provider to three cells and updates both consumers: inverted fan channel 3, 65,536 ns; normal GPU regulator channel 1, 8,000 ns. The binding permits the optional flags cell. Compiled-DTB inspection checks both consumers together.
- The fan uses ascending logical levels 0/127/191/255. Inverted PWM defaults to enabled zero-duty mode so idle has a defined signal. The power-off path handles an idle but physically enabled PWM, retained supply and zero-speed resume; mode 0 also disables that output. The host harness compiles the actual selected driver functions with fake provider/regulator callbacks to check transitions, power errors and normal GPU duty. MMIO quantization, electrical levels, tach response and thermal behavior still require physical checks.
- The diagnostic profile pins exact-release stock input hashes and measured header format. Its builder verifies current kernel/profile coherence, compiled fan/GPU cells, gzip/raw Image identity, USB ramdisk and aligned size limits. It creates components and a review manifest. Unresolved addresses, privileged entry, actual SKU, memory reservations, trained EMC and Tegra shutdown state prevent generating a device boot command.
- The kexec helper is exported from a pinned source commit, cross-built statically for ARM64 and inspected for architecture/interpreter. Only informational invocation may be tested. Loading/executing kernels and any physical device operation remain outside this batch.

The prior [Darcy build receipt](validation-darcy.json) and [harvest receipt](harvest/index.json) remain historical evidence for their exact inputs. New locks, recipes and components must travel together. A virtual pass or source regression does not pass a physical acceptance entry.

## Stock entry follow-up

The [stock inventory candidate](STOCK_BOOTSTRAP.md) has a separate source review before its build: retain the exact signed-release recovery kernel, copy only the checksum-pinned cooling modules/XUSB payload, replace the ramdisk/cmdline and recompute the v1 image ID. Every other header field, including its raw address fields, remains unchanged; the original signature is omitted. No DTB or early firmware payload is included for replacement. A newc serializer handles binary files, symlinks and initial console devices; bounds/path/format tests and an independent AOSP repack check are required.

The new init is ramdisk PID 1 only. It requires explicit opt-in, original Darcy identity and measured original-T210 fuses before any module/gadget setup. It follows the matching release's two-module cooling sequence, applies a profile-bounded idle window/temperature stop, keeps all evidence and GPT-label-selected read-only backups in RAM, and starts stock's built-in ACM interface. It runs no Android service, persistent filesystem mount, partition write or kexec operation. Physical entry and temporary boot support remain unverified and must not trigger an automatic flash fallback. Owner unlocking/data erasure requires a later explicit decision after artifact review.

The paired Windows collector requires a unique gadget COM interface with the expected VID/PID and parent serial string. It sends one fixed RAM-archive command and reads the binary stream with a unique nonce, declared size and end marker. Size/deadline checks bound the transfer, the file is created without overwriting, and no received tar is extracted automatically. Its byte-oriented stream parser is tested with binary bytes, oversized lengths and truncation using memory streams; those tests never open a COM port.
